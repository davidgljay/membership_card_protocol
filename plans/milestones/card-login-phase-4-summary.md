# Card Login — Phase 4 Summary (Build with tests)

Date: 2026-11-10 · Plan: [card-login-implementation-plan.md](../card-login-implementation-plan.md) · Code plan: [card-login-code-plan.md](../card-login-code-plan.md) · Spec changes: [card-login-spec-changes.md](../card-login-spec-changes.md)

Card login is built and works end to end on the local stack. The verifier has `verifyServerCard`, `verifyLoginResponse`, domain-binding checks, DCQL policy matching, and the Stage 2 login service scope rule. The press enforces the scope rule, `S1`, code-520 domain bindings, and `preferred_services`. The app-sdk and wallet-sdk have site-side and wallet-side login modules, and `login-router/` is a static router that passes its browser tests in Chromium, Firefox, and WebKit. A Playwright harness runs a real same-device login against the local chain, press, and IPFS: a reference site (26 lines of login integration code, under the ~50-line target), the router, and a web wallet. The site issues a signed request, the wallet validates it against the chain and signs with a device sub-card, and the site verifies the response and logs the user in as their card. The integration suite's login tests (world setup, server card accepted for the bound domain, wrong-origin phishing rejected) pass alongside all 23 existing suite files.

Building it exposed and fixed several existing gaps that login depends on. The press wrote card-update log entries unencrypted, without `card_state` or `history`. wallet-sdk posted updates in a format the press could not verify, to a path it didn't serve. The verifier could not read a sub-card's document as the contract stores it, nor read updated cards. The press's event-log reads pointed at mainnet in the local stack. Each fix is logged in the code plan (F9, F14, F15) and the specs were amended to match (change summary, 2026-11-09 and 2026-11-10 amendments).

Not yet covered, for Phase 5: the cross-device `mcard_message` path end to end (blocked on the missing sub-card ML-KEM key source, F10), DCQL `predicate` (F11), `include_children` beyond a card's own policy under today's policy addressing (F13), the dev-tests suite on Sepolia (CP4), and Python verifier parity (5.3), which now also needs the Stage 2/3 fixes.

**Unit test totals at the end of Phase 4:** verifier 204, press 203, app-sdk 192, wallet-sdk 161, RPC provider 11, router 23 unit + 27 browser.
